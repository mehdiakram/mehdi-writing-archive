About Mehdi's Digital Legacy

"A Lifetime of Thoughts, Knowledge and Experiences, Preserved for Generations."

1. The Problem of Digital Fragility

The modern web is built on shifting sands. When writers publish online, their work is usually tethered to dynamic databases (like MySQL), proprietary Content Management Systems (like WordPress), active monthly hosting subscriptions, and renewable domain names.

If an author passes away, if hosting invoices fail to renew, or if CMS code evolves into backwards-incompatibility, decades of writing can vanish overnight. This phenomenon is known as digital decay.

2. Radical Independence Architecture

This archive was designed under the principle of radical digital independence. It guarantees that Mehdi Akram's published writings will outlive their original hosting environments:

  • Zero Permanent Server Dependencies: The public archive runs as pure static HTML/CSS/JS without PHP or SQL database servers. It can be hosted on GitHub Pages or viewed directly from an offline USB drive.
  • Tri-Layer Data Redundancy: Content is preserved simultaneously in an ACID SQLite 3 database with FTS5 search, human-readable Markdown (.md) files, and deterministic JSON exports.
  • Bidirectional Reconstruction: If the database is deleted, running python scripts/restore.py --rebuild-database reconstructs the complete database from the raw Markdown files.
  • Multilingual Equity: Native support for the Bengali script (বাংলা) and English across search, frontmatter, and file paths.

3. The 3-2-1 Preservation Strategy

The archive follows the global archival 3-2-1 backup standard:

  1. Copy 1 (Active Production): The public, version-controlled GitHub repository.
  2. Copy 2 (Automated Cloud Backup): Weekly compressed snapshot packages created via GitHub Actions workflows.
  3. Copy 3 (Cold Physical Storage): Offline storage on an external hard drive or optical media, updated via python scripts/backup.py.
